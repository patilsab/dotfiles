Yes. On Arch + i3 + Rofi, this is usually caused by **Ranger being launched without a proper terminal emulator** or Rofi waiting on the process.

If you are launching Ranger directly from Rofi, don't use:

```bash
ranger
```

Instead, launch it through Terminator:

```bash
terminator -e ranger
```

### Better: create a Rofi launcher entry

If you're using a `.desktop` file, create:

```bash
mkdir -p ~/.local/share/applications
nano ~/.local/share/applications/ranger.desktop
```

Put:

```ini
[Desktop Entry]
Name=Ranger
Comment=Terminal File Manager
Exec=terminator -- ranger
Icon=system-file-manager
Terminal=false
Type=Application
Categories=FileManager;Utility;
```

Then refresh Rofi:

```bash
rofi -show drun
```

Search for **Ranger**.

### If it still freezes

Test Ranger directly from Terminator:

```bash
terminator -e ranger
```

If that works, the problem is definitely the Rofi launcher configuration.

You can also make a small wrapper, which is what I'd recommend for your setup:

```bash
mkdir -p ~/.local/bin
nano ~/.local/bin/ranger-launcher
```

```bash
#!/bin/bash
exec terminator -- ranger
```

Then:

```bash
chmod +x ~/.local/bin/ranger-launcher
```

And use this in your `.desktop` file:

```ini
Exec=/home/$USER/.local/bin/ranger-launcher
```

**One important thing:** if your goal is to have Ranger open on a specific i3 workspace (like your earlier Firefox/Terminator setup), we can also configure it so **Ranger always opens on Workspace 1 without freezing Rofi**.
